# postmortem/ — 事故档案

> 本目录入库，而且是全仓**唯一**允许写历史叙述的地方：事故怎么发生、当时现场什么样、哪句话在什么时候被
> 写下来。`pages/` 只写当下事实，`.agents/notes/` 只写当时的取舍与代价——「沿革」和「当年踩过的坑」归这里。
> 读代码前不需要读本目录；排查同类故障、写「防再发」清单、理解某条军规的来历时，才来这里。

## 命名与结构

文件名 `YYYY-MM-DD-slug.md`，slug 用小写英文连字符。日期取事故日；事故日不可考时取该事故的锚定日
（修复落地日或最早的书面记录日），并在正文写明锚定依据。

每篇必须有四节，顺序固定；节内写法自由：

| 小节 | 写什么 |
|---|---|
| `## 时间线` | 可核实的日期 + 事件，一行一条；附 commit / 文件出处 |
| `## 根因` | 机制层面为什么会坏；可核实的事实与回溯推断**分开写**，推断必须标注 |
| `## 修复` | 实际做了什么（补丁、重构、删除都算）；说清「修的是症状还是结构」 |
| `## 防再发` | 现在靠什么拦住同类故障：军规条目、页面锚点、测试、检查清单 |

## 规矩

- **事实与推断分开**：事故当时的日志、trace、真机画面多数不在库里。凡属事后推断，标「回溯推断」；
  重写的条目整体标「回溯性重建」并写清证据来源（通常是一条 `git show <commit>:<path>` 或某篇决策笔记）。
- **只写能公开的内容**：本目录入库即公开。设备序列号、真实画面里的个人信息、trace 正文、截图、密钥与内网
  端点一律不进（同 `.agents/notes/AGENTS.md` 的隐私红线，要举例就用合成数据）。
- **不改写结论**：新证据推翻旧判断时，追加一段「订正」并写日期，不重写历史。
- **防再发要落到可执行面**：写清是哪条军规、哪个锚点、哪个测试；写不出来，说明这条还没真正防住。

`postmortem/` 不取代任何文档：结论变了要同步根 `AGENTS.md` 与 `pages/`，本目录只负责解释当年发生了什么。
本目录的引用同样遵守事实标准——写进来的路径必须真实存在。

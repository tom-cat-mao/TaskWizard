# Agent Note: P0 契约表从正文降级为索引，语义下沉 pages，理由入 notes

Status: implemented

## Problem

根 `AGENTS.md` 是每个 session 的常驻上下文，但 P0 契约表在里面是**正文**：22 条主契约加 4 条子条目的完整语义
（含事件名、常量、fail-open/fail-closed 分支、审计字段）全部内联，实测 5075 词，其中契约表一项占 4099 词
（约 80%）。由此产生三个可观测的代价：

- **预算与注意力错配**：整仓的常驻成本压在少数长条目上，模型读到第 18 条时前面的细节已被稀释；
- **同一事实有多份正文**：`pages/` 已经承载用户手册，契约细节与手册章节重复描述同一机制，两边漂移后
  无法判断哪份是权威；
- **改一处要改两处**：行为变化时契约表与 `pages/` 都要同步，而契约表里没有地方写「为什么这样设计」，
  于是取舍与代价只能靠 commit message 承载——过一段时间就找不回来了。

## Decision

- **根 `AGENTS.md` 只留常驻军规与索引**：P0 表保留编号、领域、一句话军规（≤40 字）与指向 `pages/` 稳定锚点
  的链接；每条契约的完整语义以锚点为准，本表不重复展开。编号体系（1-22 加 11b/16a/16b/16c）与表格形态不变，
  新增 P0 #23（非平凡改动必须带决策笔记）指向 `.agents/notes/AGENTS.md`。
- **契约正文层在 `pages/`**：每行链接指向 `pages/*.md` 里带 `{#anchor}` attr_list 的小节；锚点 id 是链接的
  契约面，改标题不改锚点。
- **取舍与代价在 `.agents/notes/`**：`pages/` 写是什么，`.agents/notes/` 写为什么。契约正文**不**放 notes —
  两层混用会让"当时为什么这么选"和"现在必须怎么做"互相污染。
- **词数熔断**：`tests/docs/doc-budgets.json` 的 `AGENTS.md` 项从 5100 收紧为 2100（瘦身后 1948 词 + 10%，
  取整到百位），`_agents_note` 声明迁移完成、此值即硬顶，不再是「等迁移降到 1950」的占位。
- **随索引一起改正的过时措辞**：军规里的绝对化表述按源码校准（自申报敏感 + `confirm_irreversible=true`
  的组合会执行、失败分支返回错误文本而成功分支返回多模态列表、无 usage 的回退是 CJK 感知估算 + 每图
  1500、保序来自 `max_concurrency=1` 而 admission 只做互斥与终局阻断、五接缝实名、弱证据的 learned 别名
  例外、被动表读取才是不构造 store 的那一半）。

## Alternatives considered

- **维持单文件巨型 AGENTS.md（契约正文继续内联）**
  - **最强的理由**：单一信息源，读者不需要跳转；根文件自包含，离线或工具受限时也能一次读全；不存在
    「锚点失效」这一类新故障。
  - **为何被否**：增量成本已经失控——契约表 4099 词里大部分是只有改到那一块时才需要的实现细节，却按
    每次 session 计价；同时它强制了"手册/契约"双份正文的漂移面。实测瘦身后常驻成本降到 1948 词，
    而信息并未丢失，只是从"每次必读"变成"按需拉取"。
- **把契约正文放进 `.agents/notes/`**
  - **最强的理由**：notes 有天然的分篇、四格结构与"为什么"的回答，能顺带解决"契约表里写不下理由"的问题。
  - **为何被否**：notes 的规则是写**因果与代价**（Problem / Decision / Alternatives / Consequences），
    不写**当下事实**；它的状态由所在文件夹决定，会随决定被取代而迁进 `archived/`。把"现在必须怎么做"
    放进去，等于让一条不可违反的军规跟着历史一起被归档。契约正文留在 `pages/`，理由留在 notes，两层各自
    保持单一职责。
- **只把长条目（#8/#14/#18/#21）搬走，其余内联**
  - **最强的理由**：改动最小，短条目本来就只有一两行，搬走反而增加跳转次数。
  - **为何被否**：留下"有些契约在根文件、有些在 pages"的混合布局，读者无法从编号本身判断该去哪找正文；
    预算也仍会被长条目主导，无法给出一个可熔断的硬顶。

## Consequences

- **收益**：常驻上下文从 5075 词降到 1948 词（−62%），且契约语义没有丢——每条都有稳定锚点；`pages/` 成为
  契约正文的唯一归属，`AGENTS.md` 与它不再双份维护；取舍与代价第一次有了正式载体（本目录）。
- **代价**：读一条契约多一次跳转，锚点 id 成了新的兼容面（改小节标题必须保留 `{#anchor}`）；`pages/` 的
  词数预算随之上升（`pages/architecture.md`、`pages/memory.md`、`pages/safety.md` 已按扩容后重新基线）。
- **仍然脆弱**：`mkdocs build --strict` 只校验页面之间的链接，根 `AGENTS.md` 不被 mkdocs 管理，因此索引里的
  锚点存在性靠 `tests/docs/` 的引用测试与人工核对保证；`.agents/notes/` 与 `pages/` 的分工是约定，没有机器
  门禁能阻止有人把事实写进 notes。

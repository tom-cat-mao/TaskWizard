# Agent Note: AGENTS.md 层级化（根 + 子树 + 文档守卫）与 postmortem 归宿

Status: implemented

## Problem

根 `AGENTS.md` 在上一轮瘦身（见 `2026-09-15-agents-md-index-tiering.md`）后只剩军规与索引，但它仍然是
**唯一**一份 AGENTS 文件。三类内容因此被迫挤在同一处，各自的读者和读写时机都不一样：

- **全仓常驻约束**（P0 表、隐私、环境坑）——每个 session 都要读，成本按 session 计价；
- **子树编辑纪律**（改 `phone_agent/v2/` 时要知道的事：docstring 是契约真相源、策略只能挂事件总线、
  观测只有 `session.observe()`）——只有动到那棵子树时才需要，却因为没地方放而散落在根文件的军规里，
  改 v2 的人要么读不到细节，要么被迫读一整屏无关内容；
- **文档写作标准**（一事实一归宿、不写沿革、不手抄生成物）——它是 `pages/` 的纪律，不是全仓军规，
  放在根文件里既不生效（写文档的人不会为此回来翻）也不该常驻。

第二个问题是**历史叙述没有归宿**。`pages/` 按标准只写当下事实，`.agents/notes/` 只写「当时的取舍」，
于是「当年发生过什么事故、根因是什么、怎么防住的」这类内容在两个载体里都不合法：写进 `pages/` 违反
「一事实一归宿」，写进 notes 又会和「为什么这样设计」互相污染，而且 notes 的状态机（`proposed/` →
`implemented/` / `archived/`）是按**决定**走的，事故不随决定被取代。结果是 step-16 观测死锁这类
有真实教训的事故只剩 `git show ac4fa34:docs/refactor-thin-loop-v2.md` 里的一句话，新人（和下一个 agent）
复现不了它的教训。

第三个问题最小但真实：根文件里没有一条关于**改哪层跑哪层**的约定，本地默认跑全套 `pytest tests`；
也没有一条关于引包 vs 自研的取向，容易在已有成熟包的地方继续手写。

## Decision

- **建立 AGENTS.md 层级，就近约束**（参照 DeepSeek Harness 的做法：根目录放全仓常驻军规，关键子目录放
  专属 AGENTS.md，「进入哪个子目录再读哪个」，子文件保持短小——其 `packages/AGENTS.md` 以 750 词为上限，
  本项目沿用这个上限）。
  - `phone_agent/v2/AGENTS.md`（609 词）：docstring 是契约真相源、策略一律是事件总线监听器、
    坐标换算只在 `v2/coords.py`、观测只经 `session.observe()`、工具失败返回错误文本、设备操作经
    `DeviceFactory`；每条都回链根 `AGENTS.md` 的 P0 索引，不复述正文。
  - `pages/AGENTS.md`（603 词）：四条铁律（一事实一归宿、只写当下事实、不手抄生成物、代码块必须可跑）、
    锚点是兼容面、以及**字数超限三步法**（①下沉迁移 ②精简浓缩 ③改 `tests/docs/doc-budgets.json`
    并在 PR 里申请提额）。第 2-4 条的机器检查（变迁措辞、清单一致性、bash 块语法）由并行分支在
    `tests/docs/` 落地，本文件只留一句指路。
  - 根 `AGENTS.md` 的 Doc Routing 表加两行：进子树改代码 → 该子树的 `AGENTS.md`；事故与历史沿革 →
    `postmortem/`。
- **根 `AGENTS.md` 增两条 Working Agreements**（新小节，置于 Environment Gotchas 之前）：
  `Prefer maintained dependencies`（能用成熟包净删手写代码时就引包，引包与自研的取舍照样写决策笔记）与
  `改了哪层只跑哪层`（改文档跑 `pytest tests/docs`，改 v2 代码跑 `pytest tests/v2`，全量矩阵交给 CI）；
  Development Commands 的分层示例同步补上。
- **`postmortem/` 入库，作为全仓唯一允许写历史叙述的目录**：文件名 `YYYY-MM-DD-slug.md`（日期取事故日，
  不可考时取锚定日并在正文说明），每篇固定四节（时间线 / 根因 / 修复 / 防再发），事实与回溯推断必须分开写，
  隐私红线同 `.agents/notes/AGENTS.md`。首篇 `postmortem/2026-08-29-step16-observation-deadlock.md`
  按上述证据回溯重建。
- **根 `AGENTS.md` 不动预算**：新增约 60 词，靠精简既有冗余腾出空间（诊断段、Data & Privacy、
  Doc Routing 的重复行、Version Management 与 P0 #10 重复的一句），1993 → 2053 词，仍在
  `tests/docs/doc-budgets.json` 的 2100 硬顶内，不需要提额。

## Alternatives considered

**单文件根 `AGENTS.md` 继续承载一切**

- **最强的理由**：读者不用跳转，一份文件自包含；不需要为「哪个目录读哪个文件」建立新约定，
  也不会出现子文件与根文件说法冲突的问题。
- **为何被否**：它已经到顶了——上一轮瘦身把根文件压到 1993 词，其中大部分是只有改到那一块时才需要的
  实现细节，却按每次 session 计价。继续往里塞子树纪律与文档标准，预算要提额、注意力要稀释，而且
  「全局军规」与「子树纪律」在同一个列表里，读者无法按作用域区分遵循强度。层级化的收益正是把
  按需内容从常驻成本里拿出来。

**子目录规则写进各文件 docstring**

- **最强的理由**：零新增文件，规则与它约束的代码物理相邻；改那个模块的人一定看得见（docstring 本来
  就是契约真相源）。
- **为何被否**：docstring 随模块走，只能承载**单模块**的契约，承载不了跨文件的编辑纪律——「策略只能
  挂事件总线」「观测只有一个生产者」「改行为同步 `pages/` 锚点」都是对整个子树乃至跨目录的要求，
  没有一个模块是它们的家。写多份就是多份真相；写进某个模块的 docstring 又会让其他模块的人读不到。
  结论是：模块契约留在 docstring，子树纪律单独成文件。

**把事故记录并进 `.agents/notes/`（不新建 `postmortem/`）**

- **最强的理由**：少一个顶层目录，少一套命名与结构约定；notes 已有四格结构与隐私红线，机制现成。
- **为何被否**：notes 的状态由所在文件夹决定，迁移规则是「决定被取代 → 进 `archived/`、只许追加迁移说明」。
  事故不服从这个生命周期：它不会因为某个决定被推翻而失效，也不会因为新方案落地就「过期」。把两者
  混在一起，既污染「当时为什么这么选」的语义，又让事故记录被 notes 的冻结规则绑住。另立目录后，
  「哪些文件允许写沿革」变成一个可以一眼回答的问题。

**把子树规则做成 `.agents/` 下的一本手册（不分目录）**

- **最强的理由**：单一存放点，改一次全仓生效，不依赖「读者会不会进入目录再读文件」。
- **为何被否**：它把成本从根文件挪到一本没人主动打开的册子上。就近约束的全部价值在于**触发时机明确**：
  打开 `phone_agent/v2/` 里的文件时看到 `AGENTS.md`，才会读那三屏纪律。集中成册后，规则是否被读到
  取决于读者的自觉，而这正是它想解决的问题。

## Consequences

- **收益**：常驻成本不变（根 2053 词，仍在硬顶内）而总可读内容变多——子树纪律与文档标准第一次有了
  明确的触发时机；「哪里允许写沿革」有了唯一答案，step-16 事故从一句话变成可复述的档案（时间线、
  可核实 vs 回溯推断、防再发落到具体测试）；本地验证成本按改动层分流，全量矩阵回归 CI。
- **代价**：多出三个需要维护的文件（两份子树 AGENTS + `postmortem/README.md`）；规则分散后，
  改一条跨层约定要同时改根文件与子树文件，可能出现说法漂移；`postmortem/` 的结构（四节、事实/推断
  分开）目前只靠人工遵守，没有机器门禁。
- **仍然脆弱**：锚点仍无机器校验——`tests/docs/test_doc_references.py` 跳过含 `#` 的 token，P0 表里的
  `{#anchor}` 是否落地靠人工核对；两个子文件的引用真实性与词数上限已在本批纳入 `tests/docs/` 门禁
  （`_DOCUMENTS` 含 `phone_agent/v2/AGENTS.md` 与 `pages/AGENTS.md`，词数预算各 750）。
- **边界**：层级只建到「有独立纪律的子树」为止（`v2/` 与 `pages/`），不为每个目录造一份 AGENTS.md；
  `phone_agent/adb/`、`grounding/`、`config/` 作为保留库继续由根文件与模块 docstring 约束。
